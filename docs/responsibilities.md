# 分工与职责

## 机器分工

| 项目 | Mac A：控制平面 | Mac B：运行节点 |
| --- | --- | --- |
| Multica Frontend | 负责 | 不部署 |
| Multica Backend | 负责 | 不部署 |
| PostgreSQL | 负责 | 不部署 |
| HTTPS / 公网隧道 | 负责 | 不部署 |
| Multica daemon | 部署，可执行任务 | 部署，主要执行任务 |
| Agent CLI | 按需要安装 | 必须安装至少一个 |
| Git 项目目录 | 可选 | 主要存放位置 |
| 数据库备份 | 生成和验证 | 保存一份加密副本 |
| 公网入站端口 | 仅 80/443 或隧道 | 不开放 |

## 人员分工

小型团队可以由两个人分别负责，也可以由一个管理员兼任。

### 平台管理员

- 负责 Mac A、Docker Compose、域名和 TLS；
- 管理管理员账号、注册策略和 Workspace 权限；
- 升级 Multica 前先备份；
- 监控磁盘、数据库和公网入口；
- 管理数据库备份与恢复演练。

### Runtime 管理员

- 负责 Mac A/Mac B 上的 daemon；
- 安装、升级并登录 Agent CLI；
- 管理节点上的 Git 仓库和开发依赖；
- 限制节点账号可访问的文件和密钥；
- 排查 Agent 进程、环境变量和工具链问题。

### Workspace 管理员

- 邀请或移除成员；
- 设置用户角色和项目访问范围；
- 创建 Agent 并绑定正确 Runtime；
- 处理异常任务和敏感操作审批；
- 定期清理不再使用的 Agent 和会话。

### 普通用户

- 只在被授权的 Workspace 和项目中工作；
- 不在任务内容中粘贴密码、PAT 或 API Key；
- 提交任务前确认目标 Agent 和 Runtime；
- 检查 Agent 生成的代码后再合并；
- 发现越权访问或敏感信息泄露时立即报告。

## 首次上线任务表

| 任务 | 负责人 | 验收结果 |
| --- | --- | --- |
| 准备域名和 DNS | 平台管理员 | 两个域名解析完成 |
| 部署控制平面 | 平台管理员 | `/readyz` 正常 |
| 配置 HTTPS / 隧道 | 平台管理员 | 外网可访问且证书正常 |
| 注册 Runtime A | Runtime 管理员 | UI 显示在线 |
| 注册 Runtime B | Runtime 管理员 | UI 显示在线 |
| 安装 Agent CLI | Runtime 管理员 | CLI 已登录并可运行 |
| 创建 Workspace 和角色 | Workspace 管理员 | 权限测试通过 |
| 配置数据库备份 | 平台管理员 | 已生成并恢复一次 |
| 双节点任务测试 | Workspace 管理员 | 两台机器分别执行成功 |
| 编写故障联系人清单 | 平台管理员 | 团队成员可查看 |

## 变更规则

- 修改 `.env` 后使用 `docker compose ... up -d` 重新创建容器；
- 升级前记录当前版本并执行数据库备份；
- 不直接修改生产数据库；
- 不在未通知用户时重启 Mac A；
- Agent CLI 凭证变更后进行节点测试；
- 删除 Runtime 前，先将 Agent 和未完成任务迁移到其他节点。
